# End-to-end test report: 2026-11-13

Run id `QABA16DB`, 17:50–18:20 UTC. Independent QA subagent; evidence verified by the coordinator.

**Surfaces tested**
- Product page (https://takara-ai.vercel.app/)
- Hosted app (/app)
- Local dashboard (http://localhost:8787)
- Contract `treasury.takara-ai-hq.testnet`

**Scenario (founder):**
1. A business enters Takara.
2. It buys a plan.
3. It opens the dashboard.
4. It adds 3 teammates.
5. It sets weekly payroll of 10, 20 and 15 USDC, paid privately.
6. Subscription-closing alerts fire.
7. A team member sends an invoice to the agent, gets reimbursed, and the treasury releases the funds.
8. The alert is visible in the team member's dashboard.

## Verdict

**The core money engine works end to end on chain.**
- Email → intake → OutLayer TEE engine → claim → accept → authorize → settle all completed.
- The books reconcile: 1,400 in treasury − 577.5 paid − 805 reserved = 17.5 spendable.
- The policy correctly refused an automatic acceptance that would have broken the runway floor. A signer then accepted it.

**Much of the scenario as written is not built yet:**
- Buying a plan, inviting teammates and payroll setup exist only as labelled previews.
- Payroll is one aggregate payee, monthly, with no per-person or weekly schedule.
- Private payouts need a 1Click partner key; without one the API returns 401.
- The team member does not see alerts.
- On testnet, settlement moves the ledger but no tokens. This is by design: the README says real payouts are the mainnet 1Click demonstration. The app copy, however, says "Payouts already sent".
